# 通过个人微信使用 ZipClaw

本入口使用微信 ClawBot 的 iLink HTTP 通道。接入协议参考
[腾讯公开的协议说明](https://github.com/Tencent/openclaw-weixin/blob/main/docs/protocol_zh_CN.md)。
我们用 Python 实现通道，继续调用 ZipClaw 的 AgentLoop，不需要安装 OpenClaw。

只接受扫码用户的私聊文字任务，可以把本机 PNG/JPEG 图片发回手机。
接收手机图片用于模型视觉分析、语音、附件和群聊尚未接入。
微信里收到最终回答；模型流式片段和执行轮次仍在电脑终端显示。

## 1. 安装微信可选依赖

在 PowerShell 中执行：

~~~powershell
Set-Location "C:\Users\28657\Desktop\ZipClaw"
uv sync --extra wechat
~~~

微信接入使用 httpx 收发 HTTP 请求，使用 qrcode 在本机生成二维码，
使用 Pillow 检查图片，并按微信媒体协议用 cryptography 加密上传。
普通 zipclaw 命令仍然保留。使用 uv tool 安装的旧命令环境与项目 .venv
是不同环境，因此本教程通过 uv run 使用项目环境。

## 2. 扫码登录

### 在 PyCharm 中直接运行

打开 src/weixin.py，右键选择“运行”。使用项目 .venv 解释器：

~~~text
C:\Users\28657\Desktop\ZipClaw\.venv\Scripts\python.exe
~~~

首次没有微信登录记录时，会在默认浏览器弹出二维码图片；扫码确认后，
同一个程序自动继续启动微信 Agent，不需要再运行第二条命令。
已有登录记录时先尝试启动；微信报告凭证失效时，程序关闭旧连接并自动弹出
新二维码，扫码成功后继续启动，不需要手动删除登录记录。
一次启动最多自动重新扫码一次；若新凭证仍被拒绝，会明确报错并停止。
显式执行 login 命令时，也会请求新的登录凭证，不复用已失效的旧绑定。

默认工作区固定为当前用户的桌面，本机为 C:\Users\28657\Desktop，
不受 IDE 的 Working directory 影响。
要操作其它项目，修改 src/weixin.py 顶部的 WORKSPACE 变量。
窗口打不开时，终端仍展示二维码，也会显示二维码文件位置。

### 从终端登录

~~~powershell
uv run --extra wechat zipclaw-wechat login
~~~

使用手机微信扫描终端二维码，并在手机上确认。终端二维码不清楚时，
打开提示的 login.svg 文件再扫码。需要配对验证码时，程序会提示你输入。
二维码过期时重新执行登录命令。扫码授权能否完成取决于微信账号和客户端
当前是否可使用 ClawBot 通道；如果微信端提示不支持，先按微信端提示处理。

登录凭证保存到：

~~~text
C:\Users\你的用户名\.zipclaw\wechat\credentials.json
~~~

其中的 token 是微信凭证，程序不会把它打印出来，也不会发给模型。
登录命令本身不调用模型，无需先填写模型配置。

## 3. 指定工作区并启动

沿用项目 .env 中的 USTC_* 模型配置和 ZIPCLAW_* 执行配置。
无需增加微信 AppID 或公众号密钥，微信凭证由扫码获取。

需要网页搜索时，在同一份项目 .env 中填写独立的 Tavily 密钥：

~~~dotenv
TAVILY_API_KEY=你的Tavily密钥
~~~

留空或未设置时不启用 web_search，原有聊天和工具仍然可用。
搜索密钥与 USTC 模型密钥不同，调用使用 Tavily 的额度；修改后重启入口。
搜索不属于本地只读工具：受限模式下先确认关键词，完全访问模式下免确认。

微信命令入口不传 --workspace 时，也默认使用当前用户的桌面。
要操作其它目录，可以通过 --workspace 明确指定，不影响普通 zipclaw 的工作区规则。

完全访问开关放在项目 .env 中，默认关闭：

~~~dotenv
ZIPCLAW_WECHAT_FULL_ACCESS=false
~~~

- false：写文件和运行命令前需要确认，文件工具限制在工作区内。
- true：微信工具免确认执行，文件工具可使用绝对路径访问工作区外的目录。

开关只影响微信入口，不改变终端 zipclaw。相对路径仍以当前工作区为基准，
命令的启动目录也仍是工作区。完全访问不会取得超出当前 Windows 用户的系统权限，
write_file 不覆盖已有文件、edit_file 要求唯一匹配等工具规则继续保留。
修改配置后重启微信入口；默认没有自动开启完全访问。

~~~powershell
uv run --extra wechat zipclaw-wechat run --workspace "C:\Users\28657\Desktop\ZipClaw"
~~~

也可以用项目虚拟环境解释器：

~~~powershell
.\.venv\Scripts\python.exe -m zipclaw.channels.wechat.main run --workspace "C:\path\to\your-project"
~~~

保持这个进程运行，电脑保持联网。启动前确认工作区是你希望 Agent 操作的项目。
同一微信绑定只运行一个微信入口进程；入口会通过本地锁阻止重复启动。
第一版先在前台运行，后台服务和开机启动留到真实收发验证通过后再配置。

## 4. 从手机发送任务

在微信的 ClawBot 对话里发送：

~~~text
读取 README.md 的前 20 行，然后简单介绍项目。
~~~

读取、本地文本搜索和列目录直接执行。要修改文件、执行命令或联网搜索时，机器人先发工具名称、
完整参数，以及本次确认编号，例如：

~~~text
等待确认：run_command
完整参数：
{
  "command": ["git", "--version"]
}

同意：/approve a1b2c3d4
拒绝：/deny a1b2c3d4
~~~

把当前消息中的完整指令发回去即可。编号每次不同，旧编号不能确认新操作。
确认消息全部发送后，两分钟内没有确认则拒绝。普通的 y 或 yes
不会被当成微信操作确认，以免把聊天内容误认为授权。

完全访问开启时，不再出现上述确认消息。通过 /status 可以查看当前访问模式。

### 发送图片

例如项目里已经存在 output/chart.png，在微信里发送：

~~~text
把 output/chart.png 这张图片发给我。
~~~

微信入口额外注册 send_image 工具。模型调用后，程序验证图片、加密上传到
微信 CDN，再发送原生图片消息。仅在回答中输出本机路径或 Markdown
图片语法不能把图片发到手机。支持 PNG/JPEG，单张图片的应用上限为 10 MiB。
完全访问关闭时，图片也必须在工作区内；开启时允许外部绝对路径。

### 网页搜索

配置 TAVILY_API_KEY 并重启后，在微信里发送：

~~~text
搜索 Python TaskGroup 的官方文档，简单解释并附来源链接。
~~~

微信与终端共用 web_search，最多返回五条标题、链接和摘要，不读取网页全文。
受限模式会提示关键词将发给 Tavily，并等待 /approve 编号；拒绝时不调用搜索接口。
搜索失败会返回中文说明，不自动重试。/cancel 可以中断当前请求。
接口说明和完整配置步骤见 README 的 web_search 小节。

### 正在输入与安静模式

开始任务时申请微信 typing_ticket，并在任务执行期间定期更新“正在输入”。
等待用户确认时暂停，回答完成、出错或取消后关闭。
实际显示由微信客户端和接口支持情况决定；失败只记录在电脑终端，不阻止回答。

已去掉“已收到，开始处理”和忙碌提示，不会每条任务都发送状态消息。

## 5. 聊天指令

| 指令 | 行为 |
| --- | --- |
| /help | 查看帮助 |
| /status | 查看任务状态 |
| /cancel | 取消当前任务或等待中的确认，并清空待处理消息 |
| /clear | 保存空历史后清空微信会话；有任务时需先取消 |
| /approve 编号 | 同意当前这一项工具操作 |
| /deny 编号 | 拒绝当前这一项工具操作 |

同一时刻只执行一个任务。任务执行期间收到新的普通任务会在内存中按顺序排队，
当前任务结束后继续执行，不发送忙碌提示；/status 显示待处理消息数量。
排队消息开始执行时才加入模型历史，进程退出后不恢复内存队列。

电脑终端中按 Ctrl+C 停止微信入口，并取消当前任务。
已经发生的文件修改不会因取消而撤销。

## 6. 会话和收消息记录

微信会话放在 .zipclaw/wechat/sessions/ 下，以机器人账号、扫码用户、
工作区路径的哈希区分。终端原有 .zipclaw/sessions/ 不受影响。

从 ZipClaw 项目目录切换到桌面后，会使用桌面对应的会话记录。
旧工作区的会话不会被删除或迁移，切回旧目录时仍可恢复。

- conversation.json：本次微信会话及工具调用历史。
- receive-state.json：收消息游标、最近 1000 个消息 ID 和任务状态。
- archives/：上下文压缩前的历史归档。

每条消息在调用模型前记录 ID，避免重复推送造成重复执行。
收到消息后若进程突然退出，该消息不会自动重跑，也不保证已完成；
重启后先核查工作区，再重新提出任务。第一版没有持久化任务队列，
也不保证跨进程崩溃的“恰好执行一次”。

收消息遇到暂时性网络失败会等待后重试。模型请求、工具执行和发消息
不会因为通道失败而自动重跑。回复发送失败时，完整回答可在本地会话里查看。
发送接口返回成功不等于已确认手机收到，真实投递需要在微信端查看。

## 7. 本版验证范围

开发时使用模拟微信接口和模拟模型验证消息解析、HTTP 请求格式、用户限制、
去重、操作确认、取消和会话隔离。开发验证不消耗真实模型额度。
完成安装后仍需要你扫码，并在手机中验证真实的文字收发和工具操作。

~~~mermaid
flowchart LR
    A[手机微信 ClawBot] -->|文字消息| B[微信 iLink 接口]
    B -->|长轮询| C[WechatService]
    C --> D[AgentLoop]
    D --> E[模型适配器]
    E --> D
    D -->|写文件或执行命令前| C
    C -->|确认编号| B
    B --> A
    A -->|approve / deny| B
    D --> F[文件与命令工具]
    F --> D
    D -->|最终回答| C
~~~
